A program is how governance arrives in an organization: an executive sponsor, a scope, named people with agreed time, and a plan for the next couple of quarters. A first one is smaller than most people expect. It rests on six foundations: treat data as an asset in a way that changes decisions, cut the estate into domains, name owners and stewards, write a policy set short enough to read, keep a simple inventory, and fix a little data quality where people can see it. None of that requires a platform.

**In practice.** Two domains, named owners and stewards, five policies, one spreadsheet, three measured attributes. That is a complete first quarter, and order matters: domains before roles, roles before policy, policy before catalog, catalog before measurement. Get each steward's manager to agree to the time in writing, because a day job with deadlines beats governance without them.

**Where it goes wrong.** The program is run as a project with an end date. There is a charter, a burst of activity and a completion report, and the original problem is untouched: eleven policies approved and two departments still bringing different revenue figures to the same review. Governance behaves like operations. The program gets it started; something permanent has to keep it going after the launch.
