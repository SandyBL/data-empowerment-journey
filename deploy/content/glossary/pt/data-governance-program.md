Um programa é a forma como a governança de dados chega a uma organização: um patrocinador executivo, um escopo, pessoas com nome e tempo acordado, e um plano para os próximos dois trimestres. O primeiro é menor do que quase todo mundo espera. Ele se apoia em seis fundamentos: tratar dados como ativo de um jeito que mude decisões, dividir o parque de dados em domínios, nomear donos e stewards, escrever um conjunto de políticas curto o bastante para ser lido, manter um inventário simples e corrigir um pouco de qualidade de dados onde as pessoas vejam. Nada disso exige uma plataforma.

**Na prática.** Dois domínios, donos e stewards com nome, cinco políticas, uma planilha, três atributos medidos. Isso é um primeiro trimestre completo, e a ordem importa: domínios antes de papéis, papéis antes de políticas, políticas antes do catálogo, catálogo antes da medição. Consiga que o gestor de cada steward aceite o tempo por escrito, porque um trabalho do dia a dia com prazos sempre vence uma governança sem prazos.

**Onde dá errado.** O programa é conduzido como um projeto com data para acabar. Há uma carta de constituição, uma rajada de atividade e um relatório de encerramento, e o problema original continua intacto: onze políticas aprovadas e duas áreas ainda levando números de receita diferentes para a mesma reunião. Governança se comporta como operação. O programa dá a partida; depois do lançamento, algo permanente precisa sustentá-la.
